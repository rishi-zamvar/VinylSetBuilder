# Plan 04-06 — close V18, and clear gate S3

## Objective

Gate **S3** (`./Scripts/screenshots.sh` exits 0 on three clean runs) is red: plan 04-05
measured **rc=0 / rc=1 / rc=1**. One defect, **V18**, caused all three of the failures'
symptoms. This plan fixes it, replaces the presence assertion that hid it, re-clears every
other gate, and closes V18 in the ledger with both halves of a route.

The defect is already root-caused three ways by 04-05 and is **not re-diagnosed here**:

1. `CrateDetailModel.moveRows(fromOffsets:toOffset:)` writes `crate.manualOrder` for **any**
   in-range offsets. `moved()` returns the array unchanged for an identity move. `orderingMode`
   is `.manual` whenever `manualOrder != nil`. So a drag that changes nothing renders
   *Custom order* + *Restore* over the sequencer's own order.
2. `ManualOrderTests.swift:194` (identity move) asserts only the displayed order and **omits**
   the `manualOrder == nil` assertion its out-of-range sibling makes three lines above.
3. `CrateWalkUITests.swift:389` — `reorderTookEffect()` is a **presence** check on
   `restore-sequenced-order-button`. The button exists whether or not the order changed, so
   the walk reported 7 passed / 0 failed while photographing two different states.

### Task 1 — `type="auto"` `tdd="true"` — RED: the assertions that were missing

**behavior.** Two identity-move cases, in
`VinylSetBuilderCore/Tests/VinylSetBuilderCoreTests/ManualOrderTests.swift`:

- **sequenced list**: a row dragged to its own index must leave `manualOrder == nil` and
  `orderingMode == .sequenced`. This is the assertion the committed suite omits at line 194,
  plus the same for the single-row case at line 181.
- **already-manual list**: a row dragged to its own index must **preserve** the existing
  manual order byte-for-byte — it must neither rewrite it nor clear it. Both directions of
  the guard need a test, or the fix could be "clear it" and still go green.

Run `./Scripts/test.sh`. The sequenced-list assertions **must fail**. Commit red.

**done:** both new cases exist, the RED ones fail for the stated reason, commit made.

### Task 2 — `type="auto"` — GREEN: the identity guard in `moveRows`

If the order the move produces equals the currently displayed order, `moveRows` returns
without touching `crate.manualOrder`. That single guard satisfies both directions: a
sequenced list stays `nil`, a manual list keeps the order it already had.

Run `./Scripts/test.sh` — 173 green expected. Then run the **negative control**: revert the
guard, confirm the new tests redden, restore it. A guard that has never been red is a
decoration.

**done:** full suite green; negative control measured and recorded.

### Task 3 — `type="auto"` — the walk measures ROW ORDER, not button presence

`reorderTookEffect()` becomes `reorderTookEffect(from:)`, polling `sequencedRowLabels()` until
the order is a genuine **permutation** of the pre-drag order — same rows, different order —
or the 3s settle expires. The comparator is a named function so it can be controlled, and the
walk runs its own **in-band negative control**: the comparator fed a list and itself must
report `false`. Step 9 then asserts the permutation at the point the frame is photographed,
alongside (not instead of) the existing header and button assertions.

The `before` labels are read **immediately before each gesture**, inside `performReorderDrag`,
because edit mode prefixes every row label with "Remove, " and recipe 2 toggles it.

**done:** no `waitForExistence`-only success signal remains in the reorder path; the walk
carries a negative control for its own comparator.

### Task 4 — `type="auto"` — the drift bar gets a positional check

04-05's second finding: per-frame **mean** drift measured 0.0346 — inside the ±0.06 bar — on a
frame with 22,142 changed content pixels. A mean cannot see a permutation.

Add `--drift A B` to `Scripts/probe-frames.py`: reports the mean delta **and** the count of
differing pixels in the content band (below y=150), and fails when either bar is breached.
Thresholds are module constants, never flags — the file's own rule. Add a `--selftest` case
built on a **synthetic permutation**: two frames with identical means and a swapped pair of
bands, proving the mean bar alone passes it and the positional bar catches it.

**done:** `--selftest` green including the new permutation case, which is itself the negative
control for the mean-only bar.
