**The V4 defect, in source.** `App/Views/BadgePairView.swift`:

```swift
struct BadgePairView: View {
    let badges: TrackBadges
    var body: some View {
        HStack(spacing: 6) { badge(badges.bpm); badge(badges.key) }
            .foregroundStyle(badges.isIncomplete ? .secondary : .primary)   // <- the dim
    }
    private func badge(_ text: String) -> some View {
        Text(text)
            .font(.caption.monospacedDigit())
            .padding(.horizontal, 8).padding(.vertical, 3)
            .background(.thinMaterial, in: Capsule())                        // <- on near-white
    }
}
```

Light grey ink on a near-white translucent capsule, on a white List ground.

**Core's contract, which the fix must not break.** `TrackBadges` (Core) owns only strings —
`placeholder = "—"` (U+2014), `bpm`, `key`, and `isIncomplete`. **D8: Core owns no `Color`,
`Font` or `Text`.** All styling decisions live in the app target. Do not push a colour into Core.

**SEQ-11's rule, verbatim from `REQUIREMENTS.md`/`VISUAL-DEFECTS.md`:** a missing value is
*dimmed, never hidden*. So the fix has two acceptance halves, and they pull in opposite
directions:
1. the placeholder badge must be legible (V4's complaint)
2. it must still read as quieter than a complete badge (SEQ-11's rule)

Both are measured. Satisfying one is not closing the defect.

**The pattern that already works in this codebase**, established by plan 03-03 and audited
clean by 03-04 and 03-05: the thumbnail strip's status pill renders **white on a solid
saturated ground** (dark green / amber / dark red) rather than secondary-on-material, and is
legible at a glance in `03-walk-04-strip-twelve.png` and `03-walk-09-strip-scrolled-to-end.png`.
The raw list's confidence capsule does the same and carries the number as well as the colour,
so it survives a greyscale print and a colour-blind reader. **Reuse that idea; do not invent a
third badge idiom.**
