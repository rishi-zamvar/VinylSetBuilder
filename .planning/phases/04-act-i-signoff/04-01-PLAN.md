**The V2 photometric signature, from `VISUAL-DEFECTS.md` — thresholds are frozen, never tuned:**

| Signature | Threshold |
|---|---|
| a genuinely black pixel exists | `min` ≤ 110 |
| a white ground exists | `max` ≥ 200 |
| the frame is not flat | `min` ≠ `max` |

Measured on 33 frames × 3 runs: `min = 0`, `max = 255` on every frame. Per-frame mean drift
between runs: 0.022 / 0.024 / 0.029, against a stated bar of ±0.06.

**Available tooling:** Pillow 12.1.1 (`python3 -c "import PIL"` verified). No numpy assumed —

  <behavior>
    - Given a healthy frame, `--check` exits 0 and prints its dimensions, mean, min, max, md5 and byte size
    - Given a frame whose `min` is above 110, `--check` exits non-zero and names that frame as SUSPECT
    - Given a flat frame (`min == max`), `--check` exits non-zero and names it
    - `--json` emits one object per frame with keys: path, w, h, mean, min, max, md5, bytes
    - Given two frames, `--diff a.png b.png` prints the number of differing pixels and that number as a fraction of the total
  </behavior>
  <action>
    Write `Scripts/probe-frames.py` — the tool plans 02-05 and 03-05 wrote ad-hoc, ran six
    times, and never committed. Nothing in it is new; what is new is that it exists on disk.

    Interface:

    ```
    Scripts/probe-frames.py [--json] [--check] [--diff A B] [PATHS...]
    ```

    - default / `--json`: measure every PNG given (or all of `Artifacts/screenshots/*.png` if
      none given) and emit the per-frame record above. `--json` to stdout as a JSON array;
      without it, a markdown table.
    - `--check`: apply the three V2 signature thresholds. Print `SUSPECT: none` and exit 0 when
      every frame passes; print each failing frame with the value that failed and exit 1.
    - `--diff A B`: `PIL.ImageChops.difference`, convert to `L`, count non-zero pixels, print
      `differing=N total=M fraction=F`.

    **The three thresholds are constants named `MIN_DARK = 110`, `MIN_BRIGHT = 200` and are
    NOT configurable from the command line.** A tunable threshold is a threshold that gets
    tuned to make a red frame green, which is exactly the failure `VISUAL-DEFECTS.md` forbids
    in writing. Put that sentence in the module docstring, with the reference.

    Use `PIL.ImageStat.Stat(img.convert("L"))` for mean and `img.convert("L").getextrema()` for
    min/max — the same convention 02-05 and 03-05 used, so the numbers in this repo's history
    stay comparable. Record that in the docstring too.

    md5 is of the file bytes, `hashlib.md5(open(p,'rb').read()).hexdigest()`.
  </action>

    **The canonical flow map lives in this script as a literal table**, because MVP-SPEC §2 is

    where status is `COVERED` or `DEFERRED — Phase N`. Derive the rows from the §2 text quoted

    **Gate B — distinctness, measured, not counted.** Exact md5 equality is too brittle: V14's
    pair was byte-identical on one run and differed by a 41×92 px toolbar patch on the other two.
    So:

    1. Bucket frames by `(w, h, round(mean, 1))`. Frames in different buckets are different
       states and are not compared — this keeps the pass count to a handful instead of 990.
    2. Within each bucket of size > 1, run the full pixel diff and record
       `differing / total` for every pair.
    3. A pair whose differing fraction is **below `NEAR_DUPLICATE_FRACTION = 0.005`** (0.5%) is
       a near-duplicate. V14's measured 0.119% sits comfortably inside; two genuinely different
       screens do not.
    4. Every near-duplicate must appear in a module-level `DECLARED_DUPLICATES` list as
       `(frame_a, frame_b, reason)`. Seed it with exactly one entry:
       `("02-walk-08-detail-edit-mode.png", "02-walk-10-detail-restored.png",
         "V14: Restore's job IS to return to state 8, so the identity is semantically correct")`.
       An **undeclared** near-duplicate exits non-zero — that is what stops a new one being
       absorbed silently.

    The distinct-state count is then `len(frames) - len(declared_duplicate_pairs)` for the
    regenerable set, reported explicitly as *"N files, D declared duplicate pairs, N-D distinct
    screen states"*. For the crate walk that arithmetic must print **15 files, 1 declared pair,
    14 distinct states** — V14's finding, now produced by a command instead of by a person
    noticing.

    **Gate C — classification.** A file is:
    - `regenerable` if its basename matches one of the current suite's globs
      (`02-smoke-*`, `02-walk-*`, `03-03-*`, `03-04-*`, `03-walk-*`);
    - `historical` if not regenerable but named in at least one `.md` under `.planning/` or
      `docs/` — `grep -rl -F <basename> .planning docs`;
    - `orphan` otherwise.

    `sim-settled-crate-list.png` is expected to be the only orphan. **Delete it** as part of
    this task and record the deletion, with its citation count of 0, in the SUMMARY. If the
    audit finds a different or additional orphan, report it and do not delete anything you have
    not looked at — an uncited file may be uncited because a document is wrong.

    `--write-manifest` emits `Artifacts/screenshots/MANIFEST.md` containing, in order:

    the declared-duplicate table with measured fractions; and the full per-frame measurement
    table (path, dimensions, mean, min, max, bytes, md5). Header states the generating command
    and the date, so nobody hand-edits it.
