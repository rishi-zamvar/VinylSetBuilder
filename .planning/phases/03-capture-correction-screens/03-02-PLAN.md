<objective>
The Core half of the correction sheet: the editable draft of a segmentation result, and the raw
recognised text projected into rows.

Purpose: SEG-07 and OCR-04. Both are *rules* about text, so both belong in Core where they run
without a simulator — the sheet in 03-04 then holds none of them.

**Why this matters more than it looks.** Only 6 of the owner's 12 records read cleanly, and the
collection is heavy on white labels and dubplates that are absent from every database. Correction
is not the error path, it is a routine path, and it has to be fast. That is a design constraint on
this plan, not a nicety: every operation here is **one call with one argument**, because every
operation in the sheet has to be **one tap**.

Output: `SegmentationDraft`, `DraftLine`, `RawObservationRow`, `RawObservationRows`, and two
test files.
</objective>

  <name>Task 1: SegmentationDraft — split, merge up, hand-type, add, and back to Tracks</name>
  <files>
    VinylSetBuilderCore/Sources/VinylSetBuilderCore/Correction/SegmentationDraft.swift,
    VinylSetBuilderCore/Tests/VinylSetBuilderCoreTests/SegmentationDraftTests.swift
  </files>
  <behavior>
    Build every test input from **real strings measured off the owner's records** — quote them
    from `.planning/research/OCR-SPIKE.md` or CONTEXT.md. No invented track names.

    **Construction**
    - `init(vinylID:tracks:)` yields one `DraftLine` per track, in `position` order, `text` from
      `Track.rawOCRText`, `isHandEdited == false`.
    - An empty track list yields an empty draft, and `tracks()` on it returns `[]` — not a trap.

    **mergeUp — the operation the over-split Act I draft needs first (D-03-4)**
    - Merging line 2 into line 1 leaves one fewer line, whose text is the two texts joined by a
      single space, and it is the SECOND line that disappears.
      `["Da Lick", "Da Lick"] -> ["Da Lick Da Lick"]`.
    - `mergeUp` on the FIRST line is a **no-op** — there is nothing above it — and the draft is
      unchanged including line ids. Asserted explicitly.
    - `mergeUp` on an id the draft does not hold is a no-op, not a trap.
    - Four real over-split lines from `IMG_0498` — `["The Message -", "Brown", "Dom &", "Roland"]`
      — merged three times bottom-up collapse to one line reading
      `"The Message - Brown Dom & Roland"`, and `tracks()` then returns exactly one track.

    **splitLine**
    - Splits at the **word midpoint**: `"A: High Down Strange Nature"` (4 words) becomes
      `["A: High Down", "Strange Nature"]`, in place, so the line count goes up by exactly one and
      the new line sits immediately after.
    - Odd word counts favour the first line: 3 words split 2/1.
    - **A single-word line is a no-op** — `["Roland"]` stays `["Roland"]`, same count, same id.
      Asserted explicitly, because this is the boundary the rule is most likely to get wrong.
    - **Round trip:** split then mergeUp on the produced line restores the original text exactly.
      That is the negative control on both operations at once — if either silently mangles
      whitespace, the round trip reddens.

    **setText / addLine (hand entry)**
    - `setText` replaces the text and sets `isHandEdited == true`; other lines are untouched and
      keep `isHandEdited == false`.
    - `setText` to an empty or whitespace-only string **removes** the line — clearing a field is
      how a person deletes a junk line, and leaving an empty track behind would put a blank row in
      the crate.
    - `addLine()` appends one empty line with `isHandEdited == true` and a fresh id, and a second
      `addLine()` produces a **different** id.

    **tracks()**
    - Positions are contiguous `0..<n` in line order, after any sequence of edits.
    - Every track carries the draft's `vinylID`, `rawOCRText` equal to the line's text,
      `resolutionState == .pending`, `bpm == nil`, `camelot == nil`.
    - Empty and whitespace-only lines never become tracks.
    - Line ids are **stable across `tracks()`** — calling it twice returns the same track ids, so
      a screen that re-renders does not lose its selection.
  </behavior>
  <action>
    Write the test file first and watch it fail. Then implement to CONTEXT.md §4's signatures.

    `splitLine` splits on the word midpoint. That is a deliberate ceiling: cursor-position
    splitting needs a text-selection round trip the sheet does not have and XCUITest cannot drive.
    Mark it with a `ponytail:` comment naming the ceiling and the upgrade path
    (`ponytail: word-midpoint split; take a character index if the owner asks for finer control`).

    Splitting and merging must both normalise whitespace the same way — collapse runs, trim ends —
    or the round-trip assertion cannot hold. Do it in one private helper so there is one rule, not
    two that drift.

    Pure value type, `Sendable`, `Equatable`. No I/O, no view framework, and none of the banned
    purity substrings anywhere — **including doc comments**.
  </action>

  </verify>

<task type="auto" tdd="true">
  <name>Task 2: RawObservationRows — OCR-04, including the reads the trusted tier throws away</name>
  <files>
    VinylSetBuilderCore/Sources/VinylSetBuilderCore/Correction/RawObservationRows.swift,
    VinylSetBuilderCore/Tests/VinylSetBuilderCoreTests/RawObservationRowsTests.swift
  </files>
  <behavior>
    - `make(_:)` returns one row per observation, **including untrusted ones**. That is the entire
      point of OCR-04: the row you need in order to debug a bad read is the one the pipeline
      dropped. A projection that filtered to the trusted tier would be useless here — and a test
      asserts the untrusted row is present, so that mistake reddens.
    - `id` is 1-based and contiguous in input order: for n observations the ids are exactly
      `1...n`. Asserted as a set equality, not a count.
    - `confidence` is preformatted to two decimal places under `en_US_POSIX`: `1.0 -> "1.00"`,
      `0.5 -> "0.50"`, `0.3 -> "0.30"`. Asserted for all three, since the spike measured
      confidence to be effectively those three values and nothing else.
    - `isTrusted` is true at `1.0` and **false at both `0.5` and `0.3`** — a tier, not a fraction
      (spike finding 4). Both untrusted values asserted, because a `>= 0.4` threshold would pass
      on 0.3 alone and a `>= 0.6` threshold would pass on 0.5 alone; only testing both catches
      either.
    - **Boundary:** `0.999` is NOT trusted. The tier is `>= 1.0`, and a float comparison written
      as `> 0.9` would pass every other assertion in this file.
    - `text` is passed through verbatim, whitespace and all — the raw read is the evidence, so
      trimming it would destroy the thing being inspected. Asserted on a real garbled string with
      inner spacing, `"AAA: Strange Nat ure"`, and on `"·009"`.
    - An empty observation list yields an empty row list.
  </behavior>
  <action>
    Implement to CONTEXT.md §4's signature. `RawObservationRows` is an `enum` namespace with one
    static function, matching `CrateRows.make`'s existing shape.

    Do **not** sort, filter, deduplicate or trim. The order is the OCR's own reading order and the
    text is the raw read. This projection's only job is to make both renderable.
