<objective>
The inspect/correct sheet: tap a thumbnail, read the raw text the OCR actually produced, and fix
the segmentation by splitting a line, merging it upward, typing over it, or adding one.

Purpose: OCR-04 (raw recognised text inspectable on screen, for debugging a bad read) and SEG-07
(correct any segmentation result).

**This sheet is a routine path, not an error path.** Six of the owner's twelve records read
cleanly; the rest are white labels and dubplates absent from every database. Design pressure:
**every operation is one tap.** No cursor placement, no multi-select, no drag, no confirmation
dialog. The Act I draft arrives deliberately over-split — one line per trusted observation
(D-03-4) — so merge is the first thing a person will reach for and it must be the easiest.

This sheet holds **no rules**. Split, merge, hand-type and the raw-text projection were all built
and tested in 03-02.

Output: `InspectCorrectSheet`, `RawObservationListView`, and `CaptureView` presenting the sheet
from a thumbnail tap.
</objective>

  <action>
    **`RawObservationListView` (OCR-04).** A `List`/`Section` rendering
    `RawObservationRows.make(item.observations)`. One row per observation, identifier
    `inspect-raw-obs-{n}` (`staticText`), showing the raw text verbatim and the preformatted
    confidence. **Include the untrusted rows** — that is the entire point: the read you need in
    order to debug a bad read is the one the pipeline dropped. Distinguish trusted from untrusted
    visually, but never hide an untrusted row.

    Do **not** format the confidence here. `RawObservationRow.confidence` is already a `String`,
    formatted once in Core under `en_US_POSIX`, exactly as `TrackBadges` does. A second formatting
    rule in the view is how two screens start showing different numbers for the same track.

    **`InspectCorrectSheet` (SEG-07).** Presented from a thumbnail tap. Identifier
    `inspect-sheet`; `inspect-title` carries `CaptureItem.displayLabel` — **never
    `VinylEntry.label`** (D-03-6, defect V3).

    Layout, top to bottom, and the order is the design:

    1. **The track lines first.** They are the thing being corrected; the raw text is reference
       material and sits below.
       Each line is a row identified `inspect-line-{n}` containing:
       - `inspect-line-field-{n}` — a `TextField` bound to the line's text. Typing is the
         hand-entry path (SEG-07's third operation) and it is always available, on every line, with
         no mode to enter first. Commit through `draft.setText(_:to:)` on change or on submit.
       - `inspect-split-{n}` — one tap, calls `draft.splitLine(id)`.
       - `inspect-merge-up-{n}` — one tap, calls `draft.mergeUp(id)`. On the first row this is a
         no-op in Core; **disable the control there** so the affordance matches the behaviour
         rather than silently doing nothing.
       Both controls are visible on the row, not hidden behind a swipe or a context menu. A swipe
       action is one gesture plus one tap, and this sheet's whole constraint is one tap.
    2. `inspect-add-line-button` — appends an empty hand-typed line. This is the path for
       `IMG_0507`, the fixture the OCR failed outright: three junk reads and nothing usable. That
       record is only enterable by hand, and it is representative, not exceptional.
    3. **The raw text section**, `inspect-raw-text-section`, as a **collapsed disclosure** holding
       `RawObservationListView`. Collapsed by default because it is reference material — but note
       V3 was found only because someone expanded a collapsed section and looked, so 03-05
       photographs it expanded.
    4. `inspect-apply-button` — writes `draft.tracks()` back into that vinyl's `candidates` in the
       crate and dismisses. `inspect-close-button` dismisses and writes nothing.

    **Write-back.** `CrateStore` has no candidate-replacing mutator. Add the write-back in the
    smallest form that works and route every caller through it — read the crate, replace that
    vinyl's `candidates`, and commit via the existing `store.update(_:)`, which is exactly how
    `CrateDetailView.commit` already writes an edited crate back. Do not invent a second write
    path; if a helper is warranted, one private method on the sheet is enough.

    **Contrast, learned from V4:** do not render the confidence values or the trusted/untrusted
    distinction as `.secondary` on a translucent material. That combination produced a defect the
    tests could not see and only a screenshot caught.

**Fallbacks, decided in advance:**
- **Keyboard typing is unreliable in XCUITest.** `nameField.tap()` then
  `_ = app.keyboards.element.waitForExistence(timeout: 5)` before `typeText`, which is the pattern
  already proven in `CrateWalkUITests` step 2. If the keyboard still does not appear, do **not**
  fake the value through a test-only hook in the shipping app: drop the `03-04-sheet-hand-typed`
  state, record it as four states rather than five, and add a UAT row saying hand entry was
  verified in Core (03-02) but not photographed. A dropped state that is declared is worth more
  than a state manufactured by a hook.
- **The sheet does not present.** Verify `capture-thumb-1` is a `button` in the accessibility tree
  before assuming the presentation is broken — an identifier on a non-interactive container is the
  most likely cause and it is a one-line fix in 03-03's strip.
- **The simulator refuses to boot:** `xcrun simctl shutdown all; xcrun simctl boot <UDID>;
  xcrun simctl bootstatus <UDID> -b`, then re-run once.
- **A frame looks pale:** V2 protocol, in order — longer settle and re-capture first, then
  `.disabled(true)` tested **by tapping, not by looking**, then inherited styling. Never adjust a
  threshold to make a frame pass.
