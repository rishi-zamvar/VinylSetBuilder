**Fallbacks, decided in advance:**
- **The simulator refuses to boot.** `xcrun simctl shutdown all; xcrun simctl boot <UDID>;
  xcrun simctl bootstatus <UDID> -b`, then re-run once. If it still fails, `xcrun simctl erase`
  is the last resort — and it wipes the runner's container, so re-run the full test afterwards
  rather than collecting from a stale container.
- **`collect-screenshots.sh` finds no container.** It only ever copies the *current* container, so
  running it without a preceding `ui-test.sh` silently re-copies the previous run's PNGs. Always
  run the test first; if the script still reports nothing, re-run `ui-test.sh` and collect again
  before concluding the capture failed.
- **A frame looks pale.** Follow the V2 protocol, in order and without deviation: raise the settle
  delay and re-capture first; only a pallor that survives a longer delay is a styling question at
  all. Then test `.disabled(true)` **by tapping, not by looking** — disabled content dims *and*
  is untappable, so a completed walk is a categorical disproof. Never adjust a probe threshold to
  make a frame pass.
- **A walk step other than 4 or 5 goes red.** Do not loosen it. Record the failure and its
  measured cause in the summary; a weakened Phase 2 assertion is worse than a red one.
</verification>
