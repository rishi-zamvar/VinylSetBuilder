- **Slider range is 3...6, default 4.0** — clamped by `BPMRules.clampTolerance`, which already

- **Manual order overrides the sequencer (CRATE-04), and must not be silently discarded.** The

  Re-running the sequencer behind their back and snapping the list back is the failure mode this
  requirement exists to prevent.

```swift
public struct CrateSequencing: Sendable {
    /// Runs the sequencer over a crate's candidates and returns both the raw result and the
    /// order to display (manual order wins when present).
    public struct Outcome: Sendable {
        public let result: SequenceResult
        public let displayOrder: [Track]
        public let selectionByVinyl: [UUID: UUID]
    }

    public static func apply(_ result: SequenceResult, to crate: Crate) -> Outcome
}
```

`apply` logic, in order:
1. `selectionByVinyl` = for each track on the winning path, `vinylID → track.id`. This is what
   makes CRATE-07 work: selection is derived per crate from that crate's own run, and stored on
   the crate, never on the shared `VinylEntry`.
2. `displayOrder`: if `crate.manualOrder` is nil, the sequencer's order. Otherwise, take
   `manualOrder`, drop ids no longer in the result, then append any result tracks not mentioned
   in `manualOrder` (in sequencer order) at the end.
3. The `SequenceResult` passes through untouched — `notIncluded` is never reordered by manual
   arrangement.

Keep it a pure static function. The view calls `SequencerRunner` for the search and this for
the arrangement; neither does the other's job.

State and re-sequencing:
```swift
@State private var outcome: CrateSequencing.Outcome?
@State private var isSequencing = false
private let runner = SequencerRunner()

.task(id: SequenceInputs(crate: crate)) {
    isSequencing = true
    let result = await runner.run(candidates: crate.allCandidates,
                                  bpmTolerance: crate.bpmTolerance)
    outcome = CrateSequencing.apply(result, to: crate)
    // write the per-crate selection back through the store
    isSequencing = false
}
```
`SequenceInputs` is a small `Hashable` struct over the things that should trigger a re-run —
the vinyl ids, the candidate count, and the tolerance. Keying `.task` on it gives automatic
cancellation and coalescing for free; that is why plan 01-05 deliberately did not build a
debouncer.
